# Contributing

Bug reports, ideas and pull requests are all welcome.

## How these projects are made

My public projects are vibe-coded: an AI writes the code, I direct it and
test the result. I don't read the code line by line, so I review changes by
**trying them**, not by reading the diff. That shapes everything below.

## Reporting a bug or suggesting an idea

Open an issue and pick the template that fits. The more exact the steps and
versions, the faster I can reproduce it.

Security problems are different: **don't open a public issue**. See
[SECURITY.md](./SECURITY.md).

## Pull requests

- **AI-written pull requests are welcome, but you must say so.** In the pull
  request, name the tool or model and roughly how much of the change it
  wrote. Undisclosed AI changes will be closed.
- **Say how you tested it**, in plain words: what you ran it on, what you
  did, what happened. If nobody has run the change yet, say that. It's fine,
  just be honest.
- **Explain the change for someone who won't read the code.** What does it
  do differently from the user's side, and why?
- **Keep it to one thing.** One fix or one feature per pull request.
- **Follow the repository's own rules.** If a repository has an `AGENTS.md`,
  it applies to people as well as AI agents. Read it before you start.

The pull request template has a checklist for all of this.
